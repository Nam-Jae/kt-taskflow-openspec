# TaskFlow MVP — OpenSpec Proposal
> 기반 문서: `TaskFlow_프로그램정의.pdf` (4장) + `TaskFlow_스토리보드.pdf` (v2, 42슬라이드)
> 스토리보드 통합본에서 결정된 8건의 변경사항이 이 문서에 반영됨

---

## Mission

소규모 팀이 칸반 + 실시간 채팅으로 업무 진행을 한 화면에서 추적한다.

---

## Personas

| 페르소나 | 진입 화면 순서 | 핵심 행동 | 체류 시간 | 최다 API |
|---------|--------------|---------|---------|---------|
| **팀 리더** | 로그인 → 팀만들기 → 초대코드 공유 → 칸반(전체) → 채팅 | 한 화면 대시보드 | ~30분/세션 | `GET /teams/{id}/tasks` |
| **팀원** | 로그인 → 칸반(필터) → 채팅 | 내 카드(@me) 중심, 드래그 | ~5분/회, 여러 번 | `PATCH /tasks/{id}/status` |
| **신규 합류자** | 회원가입 → 초대코드 입력 → 칸반(스크롤) → 채팅(이력) | 이력 시간순 스크롤(검색 X) | 첫 세션 ~10분 | `GET /teams/{id}/messages` |

---

## Use Scenarios

1. 리더가 팀 생성 + 초대코드 발급 → 멤버 합류 → 칸반에 태스크 추가 → 진행 변경 → 채팅으로 합의
2. 신규 합류자 가입 → 초대코드로 팀 진입 → 칸반 + 채팅 이력 **1분 안에 파악** (시간순 스크롤, 검색 X)
3. PC에서 작성, 모바일에서 진행 확인. 자동 배포된 URL로 어디서나 접근

## 스토리보드 통합본 결정 8건

> Critical(1–4)는 구현 전 반드시 반영. Optional(5–8)은 구현 중 결정 가능.

| # | 항목 | PDF 원본 | 통합본 결정 | 이유 |
|---|------|---------|-----------|------|
| 1 ★ | users–teams 멤버십 | `owner_id`만 있음 | `users.team_id` 추가 (1인1팀, NULL=미가입) | DB 4테이블 제약 유지 |
| 2 ★ | 신규 합류자 행동 | 채팅 이력 '검색' | 시간순 **'스크롤'**로 변경 | 범위 외(검색)와 모순 해소 |
| 3 ★ | `PUT /tasks/{id}` 중복 | status용·title용 2개 같은 path | `PATCH /tasks/{id}/status` 분리 | REST 의미 + 칸반 드래그 별도 |
| 4 ★ | '내 태스크' 정의 | `creator_id`만 있음 | `tasks.assignee_id` 추가 (nullable) | 내가 만든 ≠ 내 태스크 |
| 5 | logout 의미 | stateless인데 endpoint 존재 | 200만 반환 (블랙리스트 X) | 범위 외 명시 |
| 6 | 권한 검증 | admin/member 구분만 | 비멤버 403, DELETE 본인만 | ACME Constraints 보강 |
| 7 | 측정 불가 NFR | 드래그 50ms·1분 파악 | 정성 검증으로 명시 | 수동 동작 확인 |
| 8 | `GET /messages/{id}` | 용도 모호 (padding) | 제거 → `GET /teams/{id}` 로 교체 | API 18개 유지 |

## In Scope (기능 5종)

| # | 기능 | 세부 내용 |
|---|------|----------|
| 1 | **인증** | 회원가입, 로그인, JWT 발급(24h), bcrypt 해시, stateless 로그아웃 |
| 2 | **팀** | 팀 생성 + 초대코드 자동 발급, 초대코드 합류, 멤버 목록, 팀 나가기 |
| 3 | **칸반 태스크** | TODO/DOING/DONE 3컬럼, 생성, 드래그 상태 변경, 제목·담당자 수정, 삭제 |
| 4 | **채팅** | 팀 단위 채팅 송수신, 폴링 5초(since= 증분), 발신자 + 시각 표시, 본인 메시지 삭제 |
| 5 | **배포** | Vercel MCP로 FE+BE 한 줄 배포 + Vercel Storage Neon (DATABASE_URL 환경변수) |

## Out of Scope (범위 외 7종)

- `[X]` **알림** — 이메일/SMS/푸시 알림 없음. 채팅 폴링으로 대체
- `[X]` **파일 첨부** — 이미지/파일 업로드 없음. 텍스트 채팅만
- `[X]` **검색** — 전문 검색 없음. 시간순 스크롤만 (단순 SELECT)
- `[X]` **권한 세분화** — 팀 owner/member 구분만. 페이지별 권한 없음
- `[X]` **다국어** — 한글 UI만. 다국어 리소스 분리 없음
- `[X]` **WebSocket** — 실시간 메시지 안 함. 5초 폴링으로 대체
- `[X]` **테스트 자동화** — pytest/jest 자동 테스트 없음. 수동 동작 확인만

## DB Schema (4테이블 + 인덱스)

> 로컬: SQLite / 배포: Neon (Vercel Storage). SQLAlchemy로 양쪽 호환.
> ★ 표시는 스토리보드 통합본에서 추가된 컬럼

```sql
-- users
id            INTEGER   PRIMARY KEY
email         TEXT      UNIQUE NOT NULL
password_hash TEXT      NOT NULL
team_id       INTEGER   REFERENCES teams(id) NULL   -- ★결정#1: 1인1팀, NULL=미가입
created_at    TIMESTAMP DEFAULT CURRENT_TIMESTAMP

-- teams
id            INTEGER   PRIMARY KEY
name          TEXT      NOT NULL CHECK(length(name) BETWEEN 1 AND 30)
invite_code   TEXT      UNIQUE NOT NULL              -- 형식: ^[A-Z]{4}-[0-9]{4}$
owner_id      INTEGER   REFERENCES users(id) NOT NULL
created_at    TIMESTAMP DEFAULT CURRENT_TIMESTAMP

-- tasks
id            INTEGER   PRIMARY KEY
team_id       INTEGER   REFERENCES teams(id) NOT NULL
title         TEXT      NOT NULL CHECK(length(title) BETWEEN 1 AND 100)
status        TEXT      CHECK(status IN ('TODO','DOING','DONE')) DEFAULT 'TODO'
creator_id    INTEGER   REFERENCES users(id) NOT NULL
assignee_id   INTEGER   REFERENCES users(id) NULL   -- ★결정#4: nullable, '내태스크' 기준
created_at    TIMESTAMP DEFAULT CURRENT_TIMESTAMP   -- ★정렬용

-- messages
id            INTEGER   PRIMARY KEY
team_id       INTEGER   REFERENCES teams(id) NOT NULL
user_id       INTEGER   REFERENCES users(id) NOT NULL
content       TEXT      NOT NULL CHECK(length(content) BETWEEN 1 AND 1000)
created_at    TIMESTAMP DEFAULT CURRENT_TIMESTAMP
```

**인덱스**
```sql
CREATE INDEX idx_tasks_team_created    ON tasks(team_id, created_at);   -- 칸반 정렬
CREATE INDEX idx_messages_team_created ON messages(team_id, created_at); -- 채팅 폴링
CREATE UNIQUE INDEX idx_teams_invite   ON teams(invite_code);            -- 합류 검증 O(1)
CREATE INDEX idx_users_team            ON users(team_id);                -- 내 팀 빠른 조회
```

## ACME

### A — Assumptions (전제)

- **1인1팀**: 사용자는 동시에 하나의 팀에만 소속. `users.team_id = NULL` = 미가입 (★결정#1)
- 단일 언어: 한국어 UI만. i18n은 범위 외
- 단일 시간대: 서버·클라이언트 모두 KST. UTC 변환 없음
- 팀당 최대 5명, 동시 접속 최대 50명
- 이메일 인증 생략: `POST /auth/signup` 즉시 계정 활성화
- 최신 브라우저: Chrome/Safari 최신 2버전. IE 지원 없음
- JWT는 `localStorage`에 저장, 서버 측 검증만 수행

### C — Constraints (제약)

- Vercel Free 티어 한도 내 운영
- 비밀번호: 반드시 bcrypt 해시 저장 (평문 금지)
- JWT 유효기간 24h, 갱신(refresh) 없음, 블랙리스트 없음 (★결정#5)
- 메시지 최대 1000자 — 클라이언트 + 서버 양쪽 검증
- 초대코드 형식: `^[A-Z]{4}-[0-9]{4}$` (예: `FRNT-2026`) — 클라이언트 + 서버 양쪽 검증
- 1팀당 1초대코드 고정. 재발급은 범위 외
- CORS 허용 도메인 명시 (와일드카드 금지)
- **권한 (★결정#6)**:
  - 모든 `/teams/*` 라우트: JWT 유효 + `user.team_id` 일치 확인, 비멤버 → `403 FORBIDDEN`
  - `DELETE /tasks/{id}`: creator 또는 team owner만 가능
  - `DELETE /messages/{id}`: 본인만 가능, owner도 타인 메시지 삭제 불가

### M — Metrics (측정 기준)

| 항목 | 기준 | 검증 방법 |
|------|------|---------|
| API 응답시간 | 100ms 이내 | 수동 측정 |
| 칸반 드래그 반응 | 50ms 미만 | 정성 검증 (★결정#7) |
| 배포 소요시간 | 5분 이내 | 수동 측정 |
| 신규 합류자 파악 시간 | 칸반 + 채팅 이력 1분 안에 | 정성 검증 (★결정#7) |
| 채팅 폴링 | 5초 간격 | `setInterval` 확인 |
| **메시지 누락 0건** | POST 성공(201) 메시지는 이후 GET 100% 노출 | since= 재동기화 확인 |
| **에러 응답 표준** | 모든 4xx/5xx → `{ error: { code, message } }` | 수동 확인 |
| **권한 격리** | 비멤버 `/teams/{other_id}/*` 접근 → 100% 403 | 수동 확인 |

### E — Examples (구체 예시)

```
# 회원가입 성공
POST /auth/signup { email, password }
→ 201 { "token": "eyJhbGc...", "user": { "id": 1, "email": "user@example.com", "team_id": null } }

# 로그인 후 분기
POST /auth/login
→ 200 { "token": "...", "user": { "id": 42, "email": "...", "team_id": null } }
  team_id=null → /signup-team(팀선택), 값 있음 → /teams/{id}(칸반)

# 초대코드 형식
invite_code: "FRNT-2026"  (정규식: ^[A-Z]{4}-[0-9]{4}$)

# 팀 합류 성공
POST /teams/join { "invite_code": "FRNT-2026" }
→ 200 { "team": { "id": 7, "name": "Frontiers", "member_count": 3 }, "redirect": "/teams/7" }

# 태스크 상태값
status: "TODO" | "DOING" | "DONE"

# 칸반 드래그 상태 변경 (결정#3)
PATCH /tasks/100/status { "status": "DOING" }
→ 200 { "id": 100, "status": "DOING" }

# '내 태스크' 필터 (결정#4)
GET /teams/7/tasks?filter=me
→ WHERE assignee_id = current_user_id  (creator_id 아님)

# 시각 포맷
created_at: "2026-05-19T10:30:00Z"  (ISO 8601)

# 채팅 폴링
GET /teams/7/messages?since=2026-05-13T14:27:00Z
→ 200 [{ "id": 23, "user_id": 42, "user_email": "user@ex.com", "content": "...", "created_at": "..." }]

# 에러 응답 표준
{ "error": { "code": "SCREAMING_SNAKE", "message": "한국어 메시지", "meta": {} } }
```

**전체 에러 코드 목록**

| HTTP | code | 발생 조건 |
|------|------|---------|
| 400 | `VALIDATION_ERROR` | 필드 형식 오류 (이메일·길이·필수) |
| 400 | `TOO_LONG` | 메시지 1000자 초과 |
| 401 | `INVALID_CREDENTIALS` | 로그인 실패 (이메일 존재 여부 노출 금지) |
| 401 | `TOKEN_EXPIRED` | JWT 만료 또는 누락 |
| 403 | `FORBIDDEN` | 비멤버가 `/teams/{id}/*` 접근 |
| 403 | `NOT_OWNER` | 타인 메시지 삭제 시도 |
| 404 | `NOT_FOUND` | 초대코드/리소스 없음 |
| 409 | `EMAIL_TAKEN` | 회원가입 시 중복 이메일 |

## Non-Functional Requirements (비기능 요구사항)

| 항목 | 내용 |
|------|------|
| **기술 스택 BE** | FastAPI (Python async) + SQLAlchemy + bcrypt + python-jose |
| **기술 스택 FE** | Vanilla JS (ES6+, fetch API) + Tailwind CSS |
| **DB 로컬** | SQLite (`sqlite:///./taskflow.db`), uvicorn으로 실행 |
| **DB 운영** | Neon PostgreSQL, `DATABASE_URL` 환경변수로 전환 |
| **성능** | API 응답 100ms 이내, 칸반 드래그 50ms 미만 (정성) |
| **보안** | JWT + bcrypt + CORS 허용 도메인 명시. 비멤버 403. 이메일 존재 여부 노출 금지 |
| **배포** | 로컬: FastAPI StaticFiles 일체형. 운영: Vercel Serverless Functions (FE+BE) + Neon |
| **안정성** | Neon 자동 백업 + point-in-time recovery (Free 기본). 로컬 SQLite는 `.gitignore` |
| **확장성** | 단일 서버 + 단일 DB. 마이크로서비스 분리 없음 (MVP 고정) |
| **관측성** | `print` 디버깅만. Sentry/로그 수집 없음 |
| **반응형** | `< 768px`: 모바일 1컬럼, `768–1024px`: 헤더 통합, `> 1024px`: 사이드 패널 |

**Claude Code에 위임 (명시하지 않음)**

- 백엔드: 라이브러리 구체 선택(Tortoise vs SQLAlchemy), 디렉토리 구조, 마이그레이션 도구
- 프론트엔드: 파일 구조(SPA vs MPA), 라우팅 방식, CSS 빌드(CDN vs 빌드), 상태 관리

## 통합 매핑표 (화면 × API × DB)

| 화면 | 주 액션 | API | DB 영향 |
|------|--------|-----|--------|
| 회원가입 | 이메일 + 비번 | `POST /auth/signup` | `users INSERT` |
| 로그인 | 인증 | `POST /auth/login` | `users SELECT` (검증만) |
| 로그아웃 | 토큰 폐기 | `POST /auth/logout` | — (stateless) |
| 팀선택 | 팀 만들기 | `POST /teams` | `teams INSERT`, `users.team_id UPDATE` |
| 팀선택 | 초대코드 합류 | `POST /teams/join` | `users.team_id UPDATE` |
| 팀선택 | 팀 정보 | `GET /teams/{id}` | `teams SELECT` |
| 멤버목록 | 조회 | `GET /teams/{id}/members` | `users SELECT (team_id=?)` |
| 칸반 | 조회 + 필터 | `GET /teams/{id}/tasks` | `tasks SELECT` |
| 칸반 | 카드 생성 | `POST /teams/{id}/tasks` | `tasks INSERT` |
| 칸반 | 상태 변경(드래그) ★ | `PATCH /tasks/{id}/status` | `tasks UPDATE (status)` |
| 칸반 | 상세 수정 | `PUT /tasks/{id}` | `tasks UPDATE (title, assignee_id)` |
| 칸반 | 삭제 | `DELETE /tasks/{id}` | `tasks DELETE (권한 검증)` |
| 채팅 | 조회(폴링) | `GET /teams/{id}/messages?since=` | `messages SELECT` |
| 채팅 | 메시지 전송 | `POST /teams/{id}/messages` | `messages INSERT` |
| 채팅 | 메시지 삭제 | `DELETE /messages/{id}` | `messages DELETE (본인만)` |
